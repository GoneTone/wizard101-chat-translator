# 術語表 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 使用者可建立多個術語表（命名、複製、刪除、匯入／匯出、引入一個內建術語表），啟用其中一個；翻譯時只把這則訊息命中的條目以 `來源 <=> 目標` 送給模型，四條翻譯路徑都套用。

**Architecture:**
- **`src/glossary/`（純邏輯，可獨立測試）**：條目解析、內建術語表註冊、比對（`Glossary::hits`）、編輯畫面用的衝突分析與匯入合併。
- **`src/config/glossaries.rs`**：config.json 裡術語表的形狀、載入時的正規化，以及「目前啟用的術語表」→ `Glossary`。
- **翻譯層**：`Translator` 的設定快照多帶一份 `Option<Arc<Glossary>>`，命中時在待翻訊息前插一組對話輪；系統訊息快取的 key 加上命中條目。
- **設定介面**：新的「術語表」分頁，清單、編輯畫面、合併對話框各一個檔案；選檔走 `SettingsEnv`，測試換假的。

**Tech Stack:** Rust、egui（`egui_kittest` 測 UI）、serde_json、`aho-corasick`（已在相依樹）、`rfd`（新增，選檔對話框）、`caseless`（既有，經 `pystr::casefold`）。

**Spec:** `docs/superpowers/specs/2026-10-24-glossary-design.md`

## Global Constraints

- 註解、docstring、UI 文字用繁體中文全形標點；log 訊息一律英文，前綴沿用 `[glossary]`（新）／`[translate]`／`[config]`／`[settings]`／`[cache]`。
- 註解預設一行、只寫 WHY；模組 `//!`、公開項目一行 `///` 摘要。
- 不可寫死語言：程式碼與提示詞不得出現 `zh`／`en`／繁中之類的判斷；內建術語表代碼只當檔名／ID。
- 新 UI 字串加進 `src/i18n/zh-TW.json`、`zh-CN.json`、`en-US.json` 三份（目前只有這三份翻到設定頁這一區），一律經 `t(key, args)` 取字。不上傳 Crowdin。
- 每句命中的條目**不可**進系統提示詞；沒有命中時送出的請求要與現在一字不差（`PROMPT_REVISION` 不動）。
- 內建術語表以 `include_str!` 編進 exe，路徑 `src/glossary/<語系代碼>.json`；清單沿用 `build_support/embed.rs` 的 `embedded_json_list` 由 `build.rs` 自動產生（同 `src/i18n/`），不手寫清單。這次不新增任何內建檔，也不改 `crowdin.yml`。

## Review Focus

1. **翻譯飛行中改了術語表（系統訊息）**：譯文要存在「翻譯當下用的命中條目」那個 key，不能存到新術語表算出的 key。→ Task 6 的 `system_translation_is_cached_under_the_key_it_was_made_with`。
2. **大小寫轉換會改變長度的文字**（`ß`→`ss`、`İ`）：比對與單字邊界都在轉換後的字串上做，不可切到字元中間而 panic。→ Task 2 的 `casefold_that_changes_length_does_not_panic`。
3. **收訊訊息的發送者剛好是術語**（`[Hollo] hi`）：發送者不參與比對，只比對內容。→ Task 5 的 `incoming_sender_is_not_matched`。
4. **使用者手改 config 寫壞術語表**（`glossaries` 不是陣列、條目值不是字串、`active_glossary` 指向不存在的 id、`builtin` 不是字串）：正規化並留 log，不 panic、不擋啟動。→ Task 4 的 `malformed_glossaries_are_normalized`。
5. **系統訊息的數字被換成 `{0}`**：查快取與存快取都以同一份樣板算命中條目，key 必須一致（含數字的術語在系統訊息不命中，這是可接受的限制）。→ Task 6 的 `lookup_and_store_use_the_same_template_key`。

### Task 2: 比對（`Glossary::hits`）

**Files:**
- Create: `src/glossary/matcher.rs`（`pub use` 到 `glossary::{Glossary, hits_key}`）
- Test: `tests/it/glossary.rs`

**Interfaces:**
- Consumes: Task 1 的 `Entry`、`fold`。
- Produces:
  - `pub struct Glossary`（`Debug`），`pub fn new(custom: Vec<Entry>, builtin: Vec<Entry>) -> Glossary`、`pub fn hits(&self, text: &str) -> Vec<Entry>`、`pub fn is_empty(&self) -> bool`。
  - `pub fn hits_key(hits: &[Entry]) -> String`：空 → `""`；否則每條 `"{source} <=> {target}"`、排序後以 `\n` 串接。

**規則（spec「比對」「衝突與優先順序」）：**
- 每條條目貢獻兩個比對字串（來源、目標的 `fold` 形式；兩者相同只算一個）；相同字串可對應多條條目，記下各自的（條目, 哪一側）。
- 原文同樣 `fold` 後比對；單字邊界與重疊都在 fold 後的字串上判斷。
- **單字邊界**：術語第一個字元若 `needs_boundary`，原文中它前一個字元不可 `needs_boundary`；結尾同理。`needs_boundary(c) = c.is_alphanumeric() && !unspaced(c)`，`unspaced` 涵蓋：CJK 統一表意文字（`3400–4DBF`、`4E00–9FFF`、`F900–FAFF`、`20000–2FFFF`）、平假名 `3040–309F`、片假名 `30A0–30FF`／`31F0–31FF`／`FF66–FF9F`、韓文 `1100–11FF`／`3130–318F`／`AC00–D7AF`、泰文 `0E00–0E7F`、寮文 `0E80–0EFF`、高棉文 `1780–17FF`、緬甸文 `1000–109F`。
- **重疊取最長**（最長的被邊界否決時，較短的要能遞補）：
  ```text
  candidates = 所有重疊比對結果（aho-corasick MatchKind::Standard + find_overlapping_iter），先濾掉邊界不成立的
  依 (start 升冪, 長度 降冪) 排序；由左到右挑：與已挑的區段不重疊才收下
  ```
- **自訂優先（以詞為單位）**：收下的區段 `w` 對應的條目中，自訂條目全送；內建條目 `e` 若 `w` 是某條自訂的**來源**，或 `w` 是某條自訂的**目標**且 `w` 在 `e` 是**來源側**，就不送；其餘照送。
- 結果依首次出現位置排序、去重（同一條不重複）。

- [ ] **Step 1: 寫失敗測試**（`e(a, b)` 為 `Entry` 建構小工具）
  - `matches_either_side_case_insensitively`：`[e("Hollo","哈樓")]`，`"I met HOLLO"` 與 `"我遇到哈樓了"` 都回 `[e("Hollo","哈樓")]`。
  - `latin_terms_need_word_boundaries`：`"Hollow Tower"` → `[]`；`"我在Hollo旁邊"` → 命中。
  - `unspaced_scripts_use_substring`：`[e("Fire Elf","파이어엘프")]`，`"파이어엘프가 왔다"` → 命中。
  - `longest_overlap_wins`：`[e("Fire","火"), e("Fire Elf","火精靈")]`，`"a Fire Elf"` → 只有 `Fire Elf`；`"Fire Elf and Fire"` → 兩條都有。
  - `shorter_term_fills_in_when_longest_fails_boundary`：`[e("Fire Elfx","甲"), e("Fire","火")]`，`"Fire Elfxy"` → `[e("Fire","火")]`。
  - `custom_overrides_builtin_on_the_shared_source`：自訂 `Fire Elf<=>火妖精`、內建 `Fire Elf<=>火精靈`；`"Fire Elf"` → 只有自訂；`"火精靈"` → 只有內建。
  - `shared_target_sends_both`：自訂 `RW<=>拉文伍德`、內建 `Ravenwood<=>拉文伍德`；`"拉文伍德"` → 兩條；`"Ravenwood"` → 只有內建。
  - `cross_side_shared_word_prefers_custom`：自訂 `哈樓<=>Hollo`、內建 `Hollo<=>哈羅`；`"Hollo"` → 只有自訂；`"哈羅"` → 只有內建。
  - `casefold_that_changes_length_does_not_panic`：`[e("STRASSE","街"), e("İstanbul","伊斯坦堡")]`，`"Straße İstanbul"` 不 panic，且命中 `STRASSE`。
  - `hits_key_is_order_independent`：兩種順序的同一組 hits 得到相同 key；`hits_key(&[]) == ""`。

- [ ] **Step 2: 跑測試確認失敗**：`cargo test -j 4 --test it glossary -- --test-threads=4` → FAIL（`Glossary` 未定義）。

- [ ] **Step 3: 實作 `Glossary`**：建構時建好 `AhoCorasick` 與「比對字串 → [(條目索引, 側, 是否自訂)]」表；`hits` 只讀。

- [ ] **Step 4: 跑測試確認通過** → PASS。

- [ ] **Step 5: Commit**：`feat(glossary): match glossary terms in both directions`

### Task 3: 衝突分析與匯入合併（編輯畫面用的純函式）

**Files:**
- Create: `src/glossary/review.rs`（`pub use` 到 `glossary::`）

**Interfaces:**
- Consumes: `Entry`、`fold`。
- Produces:
  - `pub enum RowIssue { Ok, BuiltinDiffers { other: String }, SameAsBuiltin, DuplicateSource, Incomplete }`（`Clone, Debug, PartialEq`）。`other` 是內建那條**不共用**的那一側。
  - `pub fn review(custom: &[Entry], builtin: &[Entry]) -> Vec<RowIssue>`：每條自訂一個，優先序 `Incomplete`（任一側 strip 後空白）> `DuplicateSource`（第二次以後出現的同 fold 來源）> `SameAsBuiltin`（兩側 fold 後都與某條內建相同）> `BuiltinDiffers`（與某條內建共用一個詞，且不是「只有目標對目標相同」）> `Ok`。
  - `pub fn overridden(custom: &[Entry], builtin: &[Entry]) -> Vec<bool>`：每條內建一個，有詞被自訂覆蓋（規則同 Task 2 的「自訂優先」）就是 `true`。
  - `pub fn blocks_saving(issues: &[RowIssue]) -> bool`：有 `DuplicateSource` 或 `Incomplete`。
  - `pub fn without_builtin_duplicates(custom: &[Entry], builtin: &[Entry]) -> Vec<Entry>`：去掉 `SameAsBuiltin` 的列（存檔用）。
  - `pub struct MergePlan { pub added: Vec<Entry>, pub identical: usize, pub conflicts: Vec<Conflict> }`、`pub struct Conflict { pub index: usize, pub current: Entry, pub incoming: Entry }`（`index` 是現有清單裡的位置）。
  - `pub fn plan_merge(current: &[Entry], incoming: &[Entry]) -> MergePlan`：以 fold 後的來源判斷；兩側都相同算 `identical`。
  - `pub fn apply_merge(current: &mut Vec<Entry>, plan: &MergePlan, take_incoming: &[bool])`：`take_incoming[i]` 為真就把 `conflicts[i]` 的目標換成檔案的；`added` 依序接在後面。
