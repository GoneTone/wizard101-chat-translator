# 程式內更新：更新內容視窗與自動替換重啟

## 目的

現在偵測到新版時，點更新橫幅或「關於」頁的新版連結會開 GitHub release 頁，使用者要自己下載、找到舊 exe、手動替換再重開。改成在程式裡跳出「更新內容」視窗：先讓使用者看到從目前版本之後每一版的更新內容，按「立即更新」就在程式內下載、驗證、替換 exe 並自動重啟。下載期間更新內容照樣看得到，使用者等待時可以順便讀。

UI 參考 [wuthering-waves-convene-gacha-analyzer](https://github.com/GoneTone/wuthering-waves-convene-gacha-analyzer) 的 `NewVersionDialog`（一版一張卡片、Markdown 內文），但那邊的「下載」只是開網頁，下載替換的部分是這次新設計。

## 目標

- 點更新橫幅或「關於」頁的新版連結，開「更新內容」視窗，不再開瀏覽器。
- 視窗列出所有比目前版本新的正式 release，由新到舊，一版一張卡片：版本號、發布日期、內文（Markdown 渲染，整篇照原樣）。
- 「立即更新」在程式內下載新版 exe、以 GitHub 提供的 sha256 驗證、替換、重啟。
- 下載中有進度條，可取消；取消會刪掉已下載的部分。

## 非目標

- 不做「略過這個版本」。
- 不做提權（UAC）。沒有寫入權限時失敗並提供「前往 GitHub 下載」。理由：`config.json` 與 `app.log` 都在 exe 旁邊，資料夾不可寫時程式本來就存不了設定，這個情境實際上不存在。
- 不切段顯示內文（例如只顯示跟介面語言相符的那段），整篇照原樣顯示。
- 不支援 pre-release 與草稿更新。
- 不做背景自動下載；一定要使用者按「立即更新」才開始。

## 反目標（做出來但算失敗）

- 重啟沒走正常關閉流程，遊戲記憶體裡的 hook 沒還原。
- 替換到一半失敗，使用者手上沒有可以執行的 exe。
- 取消或失敗後關掉視窗，在 exe 旁邊留下幾十 MB 的半成品檔。
- 新版啟動時撞到舊程序還沒放掉的單一實例鎖，以為已經有實例在跑就退出了，結果兩個都沒在跑。

## 限制

- 發佈形式固定是單一 exe（onefile），不能另外帶更新程式或批次檔。
- Windows 不能覆寫執行中的 exe，但可以把它改名。
- GitHub 未驗證的 API 配額是每 IP 每小時 60 次，現行每小時自動檢查一次，改用 `/releases` 列表後仍是每輪一次請求。
- 新增的 log 用英文、前綴 `[update]`；介面文字依各語系翻譯，新字串要補到每個有翻譯到該區塊的語系檔。

## 採用的做法

### Markdown 渲染：`egui_commonmark`（已選）

| 做法 | 取捨 |
|---|---|
| **`egui_commonmark` 套件（採用）** | 0.26 版支援本專案的 egui 0.37；標題、清單、連結、粗體、分隔線都有。代價是多 `egui_extras`、`pulldown-cmark` 兩個相依，exe 稍大。 |
| 只用 `pulldown-cmark`，自己寫渲染 | 樣式可完全一致，但等於重寫簡化版的 egui_commonmark，違反「不重複造輪子」。 |
| 不渲染，直接顯示原始文字 | `##`、`*`、網址原樣露出，排除。 |

### 替換與重啟：程式自己處理（已選）

| 做法 | 取捨 |
|---|---|
| **程式自己改名替換、走完 `shutdown()` 再啟動新版（採用）** | 不多帶檔案；要處理單一實例鎖的交接。 |
| 另外帶更新程式或批次檔 | 跟「exe 必須單一檔案」衝突，排除。 |

### 視窗：獨立 viewport

跟設定視窗一樣另外開一個 viewport 視窗，浮動視窗的橫幅與「關於」頁都開這個視窗。改成設定視窗裡的對話框的話，點浮動視窗的橫幅還得先開設定視窗，不採用。

## 已定案的 UI

配色、字級、按鈕、進度條沿用設定視窗的主題（`src/ui/settings/theme.rs`）與元件（`widgets.rs` 的 `primary_button`／`secondary_button`／`progress_bar`）。

### 版面

```
┌ Wizard101 聊天翻譯助手 — 更新 ─────────────── — ✕ ┐
│ 有新版本 v1.2.0                                    │
│ 目前版本 v1.0.0 · 共 2 個新版本                     │
│ ┌──────────────────────────────────────────────┐ │
│ │ v1.2.0  2026-11-03 發布  [最新]                │ │  ← 卡片清單可捲動
│ │ ───────────────────────────────────────────── │ │
│ │ （release 內文，Markdown 渲染，整篇）           │ │
│ └──────────────────────────────────────────────┘ │
│ ┌──────────────────────────────────────────────┐ │
│ │ v1.1.0  2026-10-23 發布                        │ │
│ │ ……                                            │ │
│ └──────────────────────────────────────────────┘ │
├──────────────────────────────────────────────────┤
│ （底部列：依狀態變化，見下表）                       │
└──────────────────────────────────────────────────┘
```

- 標題「有新版本 v{最新版}」，副標「目前版本 v{目前} · 共 N 個新版本」。
- 卡片由新到舊；最新那張的版本號旁加「最新」標籤（`PILL_BG`／`PILL_TEXT` 配色）。
- 發布日期取 `published_at`，換成本機時區只顯示日期（`YYYY-MM-DD`）。
- 卡片內連結點了用瀏覽器開。
- 標題與卡片在每個狀態都一樣、都能捲動，只有底部列與 ✕ 會變。

### 底部列與 ✕ 的狀態

| 狀態 | 底部列左側 | 按鈕 | ✕ |
|---|---|---|---|
| ① 尚未下載 | （空） | 稍後、**立即更新** | 可按 |
| ② 下載中 | 進度條＋「下載中 25.3 / 61.6 MB · 4.2 MB/s」 | 取消下載 | 禁用 |
| ④ 驗證中 | 進度條（滿）＋「正在驗證檔案…」 | 取消下載（禁用） | 禁用 |
| ⑤ 重新啟動中 | 進度條（滿）＋綠字「✓ 下載完成，正在重新啟動…」 | 取消下載（禁用） | 禁用 |
| ⑥ 失敗 | 紅字「更新失敗：{原始錯誤}」 | 前往 GitHub 下載、**重試** | 可按 |
| ⑦ 已取消 | 「已取消下載」 | 關閉、**重新下載** | 可按 |
| ⑧-1 下載完成，設定有沒儲存的變更 | 黃字「⚠ 設定視窗有變更還沒儲存，重新啟動後會遺失」 | 稍後、**放棄變更並重新啟動**（紅色，同刪除按鈕的配色） | 可按 |
| ⑧-2 下載完成，設定沒有沒儲存的變更 | 綠字「✓ 下載完成，可以重新啟動了」 | 稍後、**重新啟動** | 可按 |

- 「稍後」與「關閉」等同按 ✕。
- ⑧-1／⑧-2 每一幀依設定視窗的 `has_unsaved()` 自動切換；存好設定後不自動重啟，要使用者按「重新啟動」。
- 錯誤訊息只放系統或伺服器的原文，不加推測的原因。
- 驗證與重新啟動期間不能取消，避免停在替換檔案的半途。
- 「前往 GitHub 下載」開最新 release 的網頁（現行行為）。

## 行為

### 取得 release 清單

- 自動檢查（每小時）與「關於」頁手動檢查都改打 `GET /repos/GoneTone/wizard101-chat-translator/releases`，排除 `draft`、`prerelease`，留下版本號比目前新的，依版本由新到舊排序。版本比較沿用 `updater.rs` 的 `is_newer`。
- 每筆保留：版本號、`html_url`、`published_at`、`body`，以及名為 `Wizard101ChatTranslator.exe` 的 asset 的 `browser_download_url`、`size`、`digest`（`sha256:…` 去掉前綴）。
- 清單非空才算「有新版」，橫幅與「關於」頁顯示的版本號取最新那筆，行為跟現在一致。
- 實際驗證過：目前所有 release 的 exe asset 都有 `digest`。

### 下載

- 下載用 `src/local/download.rs` 的 `download()`（續傳、sha256 驗證、磁碟空間檢查、進度都有）。
- 目的地是 exe 旁邊的 `<exe 檔名>.new`（半成品是 `.new.part`）。放同一個資料夾，改名才是同一磁碟區內的原子操作。
- 進度條與速率顯示沿用本地模型下載的作法。

### 取消與清除

- 按「取消下載」：取消下載任務並刪掉 `.new.part`，進入 ⑦。取消不是暫停，不保留續傳。
- **半成品一律不留**：沒下載完就離開視窗（例如 ⑥ 下載失敗後按 ✕ 關閉），刪掉 `.new.part`。
- **已驗證的 `.new` 留到這次執行結束**：⑧ 按「稍後」或 ✕ 只關視窗、不刪 `.new`。這次執行期間再打開更新視窗，直接進 ⑧（依當下設定視窗狀態顯示 ⑧-1 或 ⑧-2），不必重新下載。下次啟動程式時清掉。
- 這次執行期間如果又查到更新的版本，已下載的 `.new` 不是最新版：刪掉 `.new`，視窗回到 ①。（設計者的決定）
- ⑥ 按「重試」從失敗的那一步接著做（同一次更新）：
  - 下載失敗：從 `.new.part` 續傳；sha256 不符時 `download()` 已經會刪檔，重試會重新下載。
  - 替換失敗（`.new` 已驗證過）：不重新下載，直接再試一次替換。（設計者的決定）

### 驗證後的設定檢查

驗證通過後檢查設定視窗（`SettingsWindow::has_unsaved()`；設定視窗沒開就視為沒有）：

- 沒有沒儲存的變更：直接替換並進 ⑤。
- 有：停在 ⑧-1，等使用者按「放棄變更並重新啟動」，或去存好後在 ⑧-2 按「重新啟動」。

### 替換

使用者在 ⑧ 按下重新啟動，或驗證後的檢查直接放行時：

1. 把執行中的 exe 改名成 `<exe 檔名>.old`（若已有舊的 `.old` 先刪）。
2. 把 `.new` 改名成正式檔名。若這步失敗，把 `.old` 改回原名，進入 ⑥。
3. 任一步失敗（例如沒有寫入權限、檔案被防毒軟體鎖住）都進入 ⑥，顯示系統錯誤原文。

### 重啟

1. 顯示 ⑤，走現有的關閉流程（`app_main.rs` 的 `shutdown_steps`：停 reader、還原 hook、卸鍵盤 hook、關翻譯池與本地模型、落盤快取）。
2. 關閉流程跑完、程序結束前，啟動新版 exe，並帶 `--after-update` 參數。新程序**沿用目前程序的權限**（直接建立子程序即可）：不提權，也不刻意降權。有使用者以系統管理員身分執行本程式（遊戲以系統管理員身分執行時必須如此，見 `notice.access_denied`），降權會讓新版掛不上遊戲。
3. 舊程序結束。
4. 新版帶 `--after-update` 時，拿不到單一實例鎖就每隔一小段時間重試，最多等幾秒（數值留給實作者決定），等不到才走原本「已有實例」的處理。沒帶這個參數時行為不變。
5. 新版啟動時刪掉殘留的 `.old`、`.new`、`.new.part`（不論有沒有帶參數），刪不掉只記 log。

啟動新版失敗時：新 exe 已經換好，舊程序照樣結束，記 log；使用者手動開就是新版。

### 進入點

- 浮動視窗的更新橫幅（`src/ui/overlay/banners.rs`）：點整列改成開更新視窗；✕ 關橫幅的行為不變。
- 設定視窗「關於」頁（`src/ui/settings/window/about.rs`）的新版連結：改成開更新視窗。
- 視窗已經開著時再點，只把它帶到前景。
- 點下去不再是直接下載，`update.available` 去掉「點此下載」那半句：zh-TW 改成「⬆  有新版本 v{version}」，en-US、zh-CN 同樣去掉對應的半句（目前只有這三個語系翻了這個字串）。橫幅與「關於」頁共用這個字串，兩邊一起變。

### log

至少記錄：取得清單的結果（版本數、最新版）、開啟／關閉視窗、開始下載（版本、大小）、下載完成／失敗（錯誤原文）、取消、清除半成品、驗證後設定檢查的結果（是否擋在 ⑧）、使用者選擇放棄變更、每一步改名的結果、啟動新版（路徑、參數）、`--after-update` 等鎖的結果、啟動時清除殘留檔。

## 留給實作者決定

- 更新視窗的大小與最小尺寸（草圖約 620×600）。
- `--after-update` 等鎖的間隔與上限。
- 更新視窗 host 跟 `settings_host.rs` 共用多少程式碼。
- `Release` 結構要擴充還是另開型別，以及事件（`UiEvent::UpdateFound`、`SettingsAction::UpdateFound`）怎麼帶清單。
- `download.rs` 目前在 `local` 模組、失敗 log 前綴是 `[local]`；變成共用後要不要搬到共用位置、log 前綴怎麼處理。
- `egui_commonmark` 的樣式怎麼調到跟設定視窗一致。
- 測試怎麼切：清單解析、版本篩選、改名與還原、清除殘留檔都能單獨測；整個下載替換重啟流程靠實機驗證。
