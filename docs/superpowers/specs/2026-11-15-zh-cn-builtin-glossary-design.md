# 簡體中文內建術語表

## 動機

內建術語表的功能已經做好，但目前一份正式的內建表都沒有。套用簡體中文漢化包的玩家，在遊戲裡看到的是漢化包的譯名；翻譯結果如果用另一套譯名，玩家會對不上遊戲畫面。這份內建表讓翻譯沿用漢化包的譯名。

## 目標

- 新增 `src/glossary/builtin/zh-CN.json`：key 是英文原文名稱，value 是漢化包的簡體中文譯名。
- 收錄範圍：法術、怪物／Boss、NPC、地名（世界、區域、關卡、副本）、寵物、坐騎、寵物天賦、徽章。
- 更新 `tests/it/glossary.rs` 裡假設「還沒有正式內建表」的測試。

## 非目標

- 不做繁體中文版：目前沒有完整的台服譯名可以對照，而且簡繁譯名差異很大，不能直接轉換。
- 不收物品、裝備、配方、家具、GUI 文字、任務標題、任務對白。
- 不把產生工具放進專案。

## 反目標（做到了也算失敗）

- 一般聊天句子大量誤命中：常見英文單字或單一中文字被當成術語，送進提示詞變成雜訊。
- 譯名混著英文、殘留括號原文，或根本沒翻。
- 同一個英文名在表裡用的譯名，和玩家在遊戲畫面上最常看到的不同。

## 做法比較

- **A. 一次性腳本，只提交 JSON（採用）**：腳本放在暫存區執行，專案只多一份 JSON 和測試修改，抽取規則記在本文件。遊戲改版或漢化包更新時，照本文件重寫腳本再產一次。
- B. 在 `examples/` 加一支 Rust 產生程式：重產方便，但專案要多維護一支依賴本機遊戲檔案、只有維護者會跑的程式。目前改版頻率不需要。
- （排除）用 Python 寫正式工具：專案已經全部是 Rust，不值得為了這個多一種語言。

## 資料來源

- 英文原文：遊戲 `Data/GameData/Root.wad` 內的 `Locale/en-US/*.lang`。
- 簡中譯名：漢化包取代的 `Data/GameData/Locale_en-US-root.wad`，內有同名、同鍵的 `Locale/en-US/*.lang`。產生當下是漢化包 6.1.2、遊戲 `W.1.620.0`。
- 兩個 wad 都是 KIWAD 格式。`.lang` 是 UTF-16，第一行是標頭，之後每三行一組：「鍵、註解、文字」。英文和中文用「檔名＋鍵」逐條對應。

## 抽取規則

1. **類別主檔**：每個類別只從自己的主檔取值，類別依下列順序排優先序：
   1. 地名 `WizardZone`、`ZoneLocName`、`Zone`、`WorldNames`、`WizardPOI`
   2. 怪物／Boss `WizardMobs`
   3. 法術 `Spells`（`Spell` 多半是描述，不收）
   4. NPC `NPCs`、`WC-NPCs`、`WizardNPC`
   5. 寵物 `WizardPets`
   6. 寵物天賦 `PetTalents`、`PetTalent`
   7. 坐騎 `WizardMounts`
   8. 徽章 `Badges`、`WizardBadges`、`ClientBadgeNames`
2. **拆開與對齊**：
   - 地名常寫成 `世界|區域`。英中兩邊 `|` 的段數相同時，逐段配對，例如 `Avalon|The Wyrd` 拆成 `Avalon → 阿瓦隆`、`The Wyrd → 寂静平原`。
   - 坐騎名稱帶租期後綴，例如 `Horse (PERM)`、`Sea Turtle (15 Day)`。兩邊都先去掉 `(PERM)`／`(N Day)` 和 `(永久)`／`(N天)` 再比對。
   - 名稱前後的引號（`" ' “ ” ‘ ’`）與空白兩邊都去掉。
3. **一個英文對一個譯名**：英文依「去頭尾空白＋casefold」去重，寫法取出現最多的。有多種譯名時，取優先序最前的類別；同一類別內取出現次數最多的，同票取先出現的。不另參考任務對白的用法 —— 漢化包各檔常各翻各的，維護者決定以主檔為準。
4. **清掉雜質**：
   - 漢化包常把譯名寫成「中文＋字面 `\n`＋英文原文」的雙語形式，例如 `缚灵仆从\nHaunted Minion`，只留中文那段。
   - 去掉譯名結尾括號裡的英文原文，例如 `暗夜沼泽城堡(Castle Darkmoor)` 改成 `暗夜沼泽城堡`。
   - 去掉之後如果仍含拉丁字母（例如 `城堡Darkmoor`）、仍有括號或 `\n`，或與原文相同（沒翻），就不收。
5. **英文原文的格式規則**，命中任一條就不收：
   - 遊戲模板碼（`$`、`#`、`\n`）
   - 含數字
   - 超過 5 個字
   - 連續空白
   - 含 `< > { } % . ! ? ( ) [ ] | _ : ; , &`
   - 內部物件名：`Ambient`／`Generic`／`Placeholder` 開頭，或以 `Ambient`／`guy`／`Preview` 結尾
   - 未使用／測試：含 `not used`、`unused`、`test`
   - 徽章的成就描述：徽章類別中以動詞開頭（`Defeat`、`Reach`、`Complete` 等），或以 `Defeats` 結尾
6. **擋掉容易誤命中的條目**：
   - **英文端**：去掉開頭的 `The ` 之後只剩一個字，而且這個字在英文任務對白裡以小寫出現過，代表它是一般單字，不收。例如 `Tempest`、`The Monster`。
   - **中文端**：中文譯名只有一個字的不收。
   - **中文端**：拿任務對白的中英兩版逐句對照，計算中文句出現這個譯名、而對應英文句沒有原文的次數（比對規則同比對器：依起點排序、同起點取最長，被前一個命中蓋住的不算）。這種「一般用語」至少 3 次、而且多於「英文句有原文」的次數，就不收，例如 `生命`、`火焰`、`诅咒`。兩個字的譯名更容易誤中，只要「一般用語」達 20 次就不收，例如 `广场`、`堡垒`。
   - 被以上規則擋掉的條目都要列成清單，給維護者確認後才定案。
   - **例外清單**：維護者確認要收的名稱，不受本條規則影響。目前有 `Spiral`、`Kraken`、`Olde Town`、`The Commons`、`School of Fire`、`Dalia Falmea`。
   - **指定對照**：維護者要收、但主檔沒有可用譯名或譯名不一致的名稱，直接指定譯名，蓋過自動結果。譯名都取自漢化包的其他檔案：
     - 學院：`Fire School → 火焰系学院`（同 `School of Fire`）；`Sun School → 太阳学院`、`Moon School → 月亮学院`、`Star School → 星界学院`、`Shadow School → 暗影学院`（取自 QuickChat）。
     - 法師稱呼（取自 MagicSchools，含複數形）：`Pyromancer → 火占师`、`Thaumaturge → 奇术师`、`Diviner → 占卜师`、`Conjurer → 咒术师`、`Theurgist → 巫术师`、`Necromancer → 死灵法师`、`Sorcerer → 幻术师`。主檔的譯法（`火术士`、`奇术`、`神学家`）各自不一致，也跟任務對白的常用譯法不同。
     - 教授：`Dalia Falmea → 达利亚·法密亚`（主檔只有姓氏 `法密亚`）。
7. **同譯名的別名照留，只拿掉內部代號與錯字**：同一個中文譯名對到多個英文時（例如 `克洛克` ← `Krokotopia`、`Krok`、`Kroks`），全部保留，只拿掉以下兩種。「對白次數」指英文任務對白裡以完整單字出現的次數。
   - **內部代號**：不含空白的駝峰字（例如 `MonthlyEvents`、`ThePhantomZoneWorld`），而且同組有一個正常寫法、對白次數不少於它的。
   - **錯字**：跟同組另一個英文只差一個字母，而且對白次數比較少（例如 `Bannana Spiders`）。單複數差異不算錯字。
8. **輸出**：JSON 物件依英文原文字母序排列。第一個鍵是 `glossary.creators`，值是 `Subata`。檔案用 UTF-8、兩格縮排。產生當下共收錄 15,149 條。

## 測試

把 `only_the_test_builtin_loads_until_real_ones_ship` 改成逐檔驗證：每份內建檔都要解析成功、濾完不為空，而且 `zh-CN` 要在 `builtin_codes()` 裡。設定頁測試如果依賴「內建表只有測試用那一份」，也要一起調整。

## 重產時的檢查

- 先抽樣每個類別的英中對照，確認漢化包格式沒變；收錄數驟減通常代表出現了新的包裝格式。
- 各類別的收錄數與擋掉原因要列成漏斗表，給維護者確認。
