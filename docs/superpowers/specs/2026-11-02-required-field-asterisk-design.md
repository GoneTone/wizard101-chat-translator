# 必填欄位標示星號

## 目的

設定視窗與首次設定精靈裡，留空就會擋下儲存或測試連線的欄位，在標籤後面加上紅色 `*`。使用者一眼就知道哪些一定要填，不必按了確定、看到紅字提示才發現。

## 範圍

判準是「這一項沒有值，程式就不能用」，與元件是文字框還是下拉選單無關。要標的欄位如下：

- **服務表單**（設定視窗與精靈共用）：名稱、服務商、模型（線上與本地兩種版面都標）、API 金鑰（只在需要金鑰、且不是自訂端點時）、伺服器網址（自訂端點）。
- **翻譯目標語言**：基本設定頁、精靈步驟。
- **翻譯服務頁**：預設服務。
- **術語表編輯**：名稱、自訂條目表頭的「來源」「目標」。

## 不做

- 有預設值或「無／跟隨預設／自動」選項的下拉不標：介面語言、思考深度、三個用途、使用的術語表、引入內建術語表、本地模型的閒置卸載與提示詞快取上限。
- 自訂端點的「API 金鑰（選填）」不標，文案維持原樣。
- 不改任何驗證邏輯，只改標籤的畫法。
- 不加「* 為必填」的說明文字（我的判斷：星號是通用慣例，有需要再加）。

## 做法

考慮過三種：

1. **程式裡畫紅色星號**（採用）：加一個共用函式，在標籤後接錯誤紅（`theme::ERROR`）的 `*`。四處畫標籤的地方改用它：服務表單的 `form_row`、設定列的 `setting_row`／`setting_row_with`、精靈的 `heading`、術語表條目的欄名。不動語系檔，效果與確認過的示意圖一致。
2. 字串直接接 ` *`：改動最少，但星號與標籤同色、不醒目，與確認過的示意圖不符。
3. 寫進語系檔：30 多個語系都要改，Crowdin 譯者可能弄丟，也做不到紅色。已排除。

使用者選了 1。

## 限制與交給實作者的部分

- **無障礙名稱不含星號**：輸入框以 `labelled_by` 指向標籤取名稱，整合測試也用 `get_by_label(tr(...))` 找欄位。星號不可讓標籤的無障礙名稱變成「名稱*」，否則螢幕報讀會多念一個符號、既有測試也會找不到欄位。怎麼做交給實作者（例如星號另外畫、或覆寫標籤的 widget info）。
- **`setting_row` 有 27 個呼叫點**：用新增變體或參數的方式都可以，但非必填的呼叫點不應被迫改寫。
- 星號緊接標籤、不留空格，標籤換行時星號跟在最後一行後面。
- API 金鑰欄的星號條件要與 `validate_endpoint_fields` 一致，不另寫一套判斷。
- 驗收：上述欄位都看得到紅色星號、其他欄位沒有；`cargo test` 全綠（既有的 `get_by_label` 測試不用改）。
