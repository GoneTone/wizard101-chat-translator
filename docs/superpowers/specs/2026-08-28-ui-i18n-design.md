# Wizard101 聊天翻譯助手：介面多語言（i18n）設計

日期：2026-08-28
狀態：已與使用者逐節確認

## 目標

介面文字目前全部硬編為繁體中文，散在 8 個檔案共約 118 條字串字面量。本設計把所有**使用者看得到的文字**抽進語言資源檔，支援繁體中文（台灣）／簡體中文（中國）／英文三種介面語言，並讓語言在設定視窗儲存後**立即生效**。

三項硬性要求：

1. **涵蓋所有顯示文字**，包含錯誤訊息、提示、橫幅、狀態指示、視窗標題。
2. **在地化用詞正確**——簡中不是繁中的字元轉換，用詞、標點、字型都要照目標地區慣例。
3. **格式相容第三方翻譯平台**（Crowdin），日後可把翻譯工作外包出去。

## 非目標

- README 多語版本（另開）。
- `crowdin.yml` 與 CI 同步（格式已相容，等實際要接平台時再加）。
- 把語言檔放到 exe 旁供使用者自行擴充語言。
- `translator.py` 的 LLM 提示詞多語化（見下方「不進 i18n 的三類」）。

## 決策摘要

| 決策點 | 結論 |
|---|---|
| 文案格式 | **JSON**（`src/i18n/*.json`，扁平 key-value） |
| 為何不用 gettext | Crowdin 支援最好，但需 `msgfmt` 編譯步驟、`babel` 相依、`.mo` 進打包；且原文即 key，繁中改字會讓三語全部轉 fuzzy |
| 為何不用 Python dict | Crowdin **不支援** `.py` 原始碼格式，只能自架 Custom File Format App（需提供 parse／build 兩支 HTTP endpoint），成本遠超需求 |
| 介面語言來源 | config 頂層新增 `ui_language`；`None` ＝首次啟動，走系統語言偵測 |
| 與 `target_language` 的關係 | **兩個獨立欄位**。首次設定時 `target_language` 預設跟隨介面語言，之後互不干涉 |
| 生效時機 | 儲存後立即生效（不需重啟） |
| 來源語言（source of truth） | `zh-TW`，也是 fallback 對象 |
| 字型 | 隨介面語言切換，抽出 `src/ui/fonts.py` |

## 一、i18n 核心模組

新增 `src/i18n/` 套件，單一職責＝**提供當前語言的文案字串**。不碰 UI、不碰 config 讀寫。

```
src/i18n/__init__.py   # t() / set_language() / current_language() / detect_system_language()
src/i18n/zh-TW.json    # source of truth（上 Crowdin 的來源檔）
src/i18n/zh-CN.json
src/i18n/en.json
```

### 公開介面

| 函式 | 行為 |
|---|---|
| `t(key, **kwargs)` | 取當前語言字串，以 `str.format(**kwargs)` 代入變數 |
| `set_language(code)` | 切換當前語言（`"zh-TW"`／`"zh-CN"`／`"en"`），lazy 載入並快取 |
| `current_language()` | 回傳目前語言碼，供設定視窗與字型模組查詢 |
| `detect_system_language()` | 偵測 Windows 使用者介面語言，回傳上述三碼之一 |
| `LANGUAGES` | `{"zh-TW": "繁體中文（台灣）", "zh-CN": "简体中文（中国）", "en": "English"}` |

`LANGUAGES` 的顯示名稱是 **endonym（該語言自稱）**，在任何介面語言下都顯示原樣、不翻譯——這是語言選單的通行慣例。

### 兩層 fallback

翻譯平台上「譯文未完成」是常態，缺字串不得讓介面炸開：

1. 當前語言缺 key → 退回 `zh-TW`
2. `zh-TW` 也缺 → 回傳 key 字串本身
3. `.format()` 拋 `KeyError`／`IndexError`（譯者把 `{count}` 打壞）→ 改用 `zh-TW` 的字串再 format

每次 fallback 都寫 stderr（落進 `app.log`），訊息用英文並帶足 context：

```python
print(f"[i18n] missing key: {key} lang={code}", file=sys.stderr)
print(f"[i18n] format failed: key={key} lang={code} error={exc}", file=sys.stderr)
```

### 系統語言偵測

```
ctypes.windll.kernel32.GetUserDefaultUILanguage()  →  LCID
locale.windows_locale[lcid]                        →  "zh_TW" 之類
```

映射規則：`zh_TW`／`zh_HK`／`zh_MO` → `zh-TW`；`zh_CN`／`zh_SG` → `zh-CN`；其餘一律 → `en`。任何例外（非 Windows、查表失敗）都退 `en` 並寫一行 log。

不使用 `locale.getdefaultlocale()`：Python 3.13 起 deprecated、3.15 移除。

### 打包

`build.spec` 的 `datas` 加入 `[("src/i18n/*.json", "i18n")]`。模組內解析資源目錄：

```python
def _i18n_dir() -> Path:
    if getattr(sys, "frozen", False):
        return Path(sys._MEIPASS) / "i18n"   # PyInstaller 解壓暫存區
    return Path(__file__).resolve().parent
```

與 `config.app_dir()`（exe 旁的可寫目錄）基準不同，**不共用**：語言檔是唯讀資源，config 是可寫使用者資料。

## 二、config 欄位

頂層新增：

```python
"ui_language": None,   # 介面語言；None＝尚未選過，啟動時依系統語言自動判定
```

啟動流程（`main.py`）：

```
load_config()
  → cfg["ui_language"] or detect_system_language()
  → set_language(...)
  → 若 is_configured() 為 False 則跑首次設定精靈
```

精靈完成或設定視窗儲存後，`ui_language` 一定是具體語言碼。

## 三、文案盤點與 key 命名

key 採 `<領域>.<用途>` 扁平命名（Crowdin generic JSON 對扁平結構最單純）。

| 領域前綴 | 來源檔 | 條數 | 例 |
|---|---|---|---|
| `app.*` | `config.py` | 1 | `app.name` → `Wizard101 對話翻譯助手` |
| `notice.*` | `main.py` 橫幅 | 5 | `notice.pending`、`notice.config_error` |
| `status.*` | `main.py` 狀態指示 | 4 | `status.listening` → `●  監聽中` |
| `input.*` | `composer/input_box.py` | 6 | `input.hint`、`input.too_long` |
| `wizard.*` | `ui/wizard.py` | 11 | `wizard.step.api`、`wizard.intro` |
| `settings.*` | `ui/settings.py` | 29 | `settings.title`、`settings.advanced.poll_hint` |
| `field.*`／`hint.*`／`error.*`／`provider.*` | `ui/fields.py` | 39 | `error.need_api_key`、`hint.model_idle` |

表列 95 條是納入 i18n 的範圍；其餘 23 條見下方「不進 i18n 的三類」（`translator.py` 19 條、`mem_reader.py` 3 條、`config.py` 的 `target_language` 預設值 1 條），合計 118 條。

另新增 1 條不在既有 118 條內的文案：`hint.custom_endpoint`。

### 不進 i18n 的三類

1. **`translator.py` 的 19 條提示詞**——給 LLM 的內部指令，語言已由 `target_language` 參數化；改寫等於重新調校翻譯品質，與本需求無關。
2. **`reader/mem_reader.py` 的 3 條 `GameNotRunning` 例外訊息**——只流向 stderr／`app.log`（`main.py:140`），使用者看到的是 `notice.game_missing` 橫幅。依 CLAUDE.md「log 訊息一律英文」，這 3 條是既有的規則違反，本次順手改為英文：

   ```python
   GameNotRunning(f"chatlog read failed (likely left the game): {exc}")
   GameNotRunning(f"game process not found: {self.process_name}")
   GameNotRunning(f"failed to attach to game: {exc}")
   ```

3. **符號與品牌名**——overlay 的 `≡ ✕ ─ ⚙`、`ChatGPT（OpenAI）`／`Claude（Anthropic）`、`COMMON_LANGUAGES` 的 endonym 清單（`日本語`、`한국어`…）。只有 `自訂端點` 需要 key（`provider.custom`）。

### 帶變數的字串一律具名 placeholder

讓譯者能自由調整語序：

| 現況 | key | zh-TW | en |
|---|---|---|---|
| `f"{APP_NAME} — 設定"` | `settings.title` | `{app} — 設定` | `{app} — Settings` |
| `f"找到 {n} 個模型：…"` | `hint.model_found` | `找到 {count} 個模型：輸入關鍵字可篩選，清單外的模型名稱也能自行輸入。` | `Found {count} models. Type to filter, or enter a name that is not listed.` |
| `" 字，超過遊戲上限 " + …` | `input.too_long` | `譯文 {count} 字，超過遊戲上限 {limit} 字——請刪減或分段後重送` | `Translation is {count} characters, over the game limit of {limit} — trim it or split it up.` |
| `f"API 設定有誤（HTTP {s}），…"` | `error.api_http` | `API 設定有誤（HTTP {status}），請檢查各欄位` | `API settings are invalid (HTTP {status}). Check each field.` |

`input_box.py:162` 現在是用字串相接拼出來的（`" 字，超過遊戲上限 " + str(n) + " 字——請刪減"`）。這種拼接在英文語序下必壞，一律改為單一 key ＋ placeholder。

### `COMMON_LANGUAGES` 補上 `English`

原本沒有（預設介面是中文，翻成英文的需求少）。英文介面使用者需要它作為 `target_language` 的預設值。

## 四、呼叫端改造

核心約束：**模組層不得再有求值後就固定的文案常數**，全部下沉到呼叫當下取字串，否則「儲存後立即生效」不成立。

### `main.py`

- `PENDING_NOTICE`／`TRANSLATE_FAILED_NOTICE`／`GAME_MISSING_NOTICE`／`OFFLINE_NOTICE`／`CONFIG_ERROR_NOTICE` 五個常數刪除，改在使用點呼叫 `t("notice.…")`。
- `STATUS` dict 刪除：**state key 直接傳給 overlay**（`overlay.set_status("listening")`），由 overlay 持有 key、顯示時才翻譯——常駐視窗要能在語言切換後就地重繪，只有它記得住 key 才辦得到。顏色表 `STATUS_COLORS` 一併搬進 `overlay.py`（顏色是顯示屬性）。
- `banner_for()` 改為**回傳 key 或 `None`**，由 overlay 翻譯。純判斷邏輯不碰 i18n，測試可斷言 key。
- `TranslationPool` 的 `failed_notice: str` 改為 `failed_notice_fn: Callable[[], str]`——建構當下就定案的字串會停在舊語言。
- `apply_settings()` 在偵測到語言變更時呼叫 `overlay.refresh_labels()`（`set_language()` 已由設定視窗在 `on_save()` 之前套用）。

### `ui/fields.py`

- `MODEL_HINT_IDLE`／`MODEL_HINT_NO_LIST`／`MODEL_HINT_EMPTY`／`LANGUAGE_HINT`／`THINKING_HINT`／`AUTO_INPUT_LABEL` 常數刪除。
- `Provider.label` 改為 `label_key`，顯示時才 `t()`。品牌名（`ChatGPT（OpenAI）`／`Claude（Anthropic）`）也給 key，三語內容幾乎相同（英文版用半形括號）——radio 標籤走同一條取值路徑，比在顯示端分支判斷乾淨。
- `validate_api_form()`／`validate_endpoint_fields()` 改為**回傳 key 列表**，由顯示端翻譯。
- `friendly_error()` 回傳 **`(key, kwargs)`**：其中兩種錯誤帶變數（HTTP 狀態碼、例外訊息），單一 key 表達不了；顯示端一律 `t(key, **kwargs)`。
- 新增 `UiLanguageField`：`ttk.Combobox`（`state="readonly"`），選項為 `LANGUAGES` 的三個 endonym。與既有 `LanguageField`（`target_language`，可自由輸入任意語言名稱）是不同元件、不同用途。
- `hint.custom_endpoint` 掛在「伺服器網址」欄位下方：`填入任何 OpenAI API 相容端點的網址，例如 LM Studio、Ollama、vLLM。`

### `ui/settings.py`

- 每次 `open()` 重建 `Toplevel`、`_save()` 結束即 `destroy()`，語言切換天然生效，**不需特殊刷新機制**。
- 「基本」分頁最上方新增「介面語言」下拉。
- `_save()` 寫入 `cfg["ui_language"]`、呼叫 `set_language()`，然後才呼叫 `on_save()`。

### `ui/wizard.py`

新增 `STEP_LANG = 0`，變成三步：**語言 → API → 偏好**。

難點：`ApiFields`／`LanguageField`／`HotkeyField` 是跨步驟保留的元件（建一次、切步驟時 `pack_forget`），語言一換它們的標籤不會更新。

**解法：整個精靈重建**，而非逐一刷新標籤。

```
語言下拉變更
  → _collect_into_cfg()      # 從 _finish() 抽出，兩邊共用
  → self.restart = True
  → self._win.destroy()

run_wizard() 外層 while 迴圈
  → 看到 restart 就以新語言重建 SetupWizard，回到語言頁
```

取捨：重建後 `ApiFields.test_passed`／`_skip_test` 會重置，需重測連線。可接受——語言通常在第一步選一次就不再更動；換來的是「絕不可能有漏刷新的標籤」。若改採 lazy 重建欄位元件，狀態管理複雜度明顯上升，不划算。

**語言頁同時決定 `target_language` 預設值**：`zh-TW` → `繁體中文（台灣）`、`zh-CN` → `简体中文（中国）`、`en` → `English`。**只在使用者尚未動過該欄位時才連動**（判斷方式：目前值仍等於前一個介面語言的對應值）；動過就不覆蓋。

### `reader/overlay.py`

- 標題列 `≡ {APP_NAME}` 與 `.title(APP_NAME)` 是建立時取一次的靜態文字。新增 `refresh_labels()`，由 `main.py` 的 `apply_settings()` 在語言變更時呼叫，一併更新標題列文字與字型。
- 狀態指示、錯誤橫幅、placeholder 都是動態更新，本來就會跟著換語言。
- **已經印在畫面上的舊訊息不回溯改寫**（含當時的「翻譯中…」佔位文字）。使用者已確認可接受。

### `config.py`

`APP_NAME` 常數改為 `app_name()` 函式（回傳 `t("app.name")`）。被 `overlay.py`、`settings.py`、`wizard.py` import，三處呼叫端一併改。

## 五、字型

`"Microsoft JhengHei"` 目前硬編在 **15 處**（`overlay.py` 9、`wizard.py` 2、`input_box.py` 2、其餘 2）。微軟正黑體雖能顯示簡體字，但字形是台灣標準，簡中使用者看會覺得字長得怪；英文介面用它也不如 Segoe UI。

新增 `src/ui/fonts.py`：

```python
def ui_font(size: int, weight: str | None = None) -> tuple:
    """依當前介面語言回傳 tkinter 字型 tuple。"""
```

| 語言 | 字族 |
|---|---|
| `zh-TW` | Microsoft JhengHei |
| `zh-CN` | Microsoft YaHei |
| `en` | Segoe UI |

15 處硬編全部改呼叫 `ui_font(...)`——這同時消除既有重複（符合 CLAUDE.md「不要重複造輪子、可共用就抽出來」）。

（實際結果：`ui_font()` 涵蓋的是 tk 直接繪製的介面——`overlay.py`、`input_box.py`，以及 `wizard.py` 裡兩處明確帶 `font=ui_font(...)` 覆寫的 `ttk.Label`；`settings.py` 與 `fields.py` 的欄位同樣是 ttk 元件，但沒有覆寫字型，於是繼承 ttk 主題字型，本就會跟著作業系統語系走，不需要、也沒有呼叫 `ui_font()`。）

字型的立即生效範圍與文案相同：`Toplevel` 類（設定視窗、精靈、輸入框）下次開啟即為新字型；overlay 常駐 widget 由 `refresh_labels()` 一併更新；已繪製的訊息不回溯。

## 六、在地化用詞方針

**簡中不是繁中的字元轉換**——逐條重寫，不做機械轉碼。關鍵對照：

| 繁中（台灣） | 簡中（中國大陸） | 英文 |
|---|---|---|
| 設定 | 设置 | Settings |
| 進階 | 高级 | Advanced |
| 自訂端點（OpenAI API 相容） | 自定义端点（OpenAI API 兼容） | Custom endpoint (OpenAI-compatible) |
| 重新整理 | 刷新 | Refresh |
| 連線成功 | 连接成功 | Connected |
| 金鑰 | 密钥 | API key |
| 伺服器 | 服务器 | Server |
| 訊息 | 消息 | Message |
| 略過測試 | 跳过测试 | Skip test |
| 首次設定（精靈） | 首次设置（向导） | Setup |
| 即時預覽 | 实时预览 | Live preview |
| 逐則排隊 | 逐条排队 | one at a time |
| 檔案／視窗／程式 | 文件／窗口／程序 | — |
| 預設 | 默认 | Default |
| 儲存 | 保存 | Save |
| 瀏覽… | 浏览… | Browse… |
| 譯文 | 译文 | Translation |
| 輪詢間隔 | 轮询间隔 | Poll interval |
| 熱鍵 | 热键 | Hotkey |

### 標點

CLAUDE.md 的「標點依語言慣例」按**目標語言各自套用**：

- **繁中**：全形，引號用直角引號 `「」`。
- **簡中**：同樣全形，但**引號用彎引號 `“”`**（直角引號是台／日慣例，簡中不用）。
- **英文**：全部半形；破折號 `—` 兩側加空格；不用驚嘆號。

### 英文文案風格

- 標籤用 sentence case（`Custom endpoint`，不是 `Custom Endpoint`）。
- 錯誤訊息寫成完整句子，句尾加句號。
- 例：`⚠  遊戲未就緒／連線中斷，等待中…` → `⚠  Game not ready or disconnected — waiting…`

## 七、測試

### 新增 `tests/test_i18n.py`

- 三個 JSON 的 **key 集合完全相同**（漏翻的主要防線）。
- 每個 key 的 `{placeholder}` 名稱集合三語一致（防譯者打壞變數）。
- `t()` 的兩層 fallback：缺 key → `zh-TW`；`zh-TW` 也缺 → 回傳 key 本身；format 失敗 → 退 `zh-TW`。
- `detect_system_language()` 的 LCID 映射（monkeypatch 查表，不依賴實機 locale）。
- JSON 無重複 key（`json.load` 會靜默保留後者，用 `object_pairs_hook` 擋）。

### 新增 `tests/test_no_hardcoded_ui_text.py`

以 `ast` 掃 `src/main.py`、`src/ui/`、`src/composer/`、`src/reader/overlay.py`，**字串字面量不得含 CJK**（排除 docstring 與註解，白名單 `COMMON_LANGUAGES` 的 endonym 與 `i18n.LANGUAGES`）。未來新增文案忘了走 i18n 會直接紅燈。

### 既有測試修正

`validate_*`／`friendly_error` 改回傳 key 後，以下斷言一併改為斷言 key（比現在比對中文子字串更穩固）：

## 八、實機驗收

pytest 之外必須實跑（本設計判定為 architectural 的主因）：

1. **三種語言各開一次 exe，檢查設定視窗與精靈沒有切字。** 英文字串普遍比中文長，現有 `minsize(640, 560)`（設定視窗）／`minsize(540, 540)`（精靈）是照中文文案調的，很可能要放寬；`responsive.bind_wrap` 也要複查。
2. 簡中／英文介面下 overlay 標題列、狀態指示、橫幅**字型正確**（Microsoft YaHei／Segoe UI）。
3. 設定視窗改語言 → 儲存 → overlay 標題列與狀態**立刻換語言，不需重啟**。
4. 首次精靈在語言頁改語言 → 精靈以新語言重建，且已填的 API 欄位值保留。
5. 首次啟動（刪掉 `config.json`）在簡中／英文 Windows 上會自動選到對應語言。
