# 測試連線可停止 —— 設計

## 為什麼

- 測試連線一開始就停不下來：按鈕停在灰色的「測試中…」，只能等結果，最久等到請求總逾時（10 分鐘）。本地大模型第一次測試要先載入，等很久是常態。
- 顯示的「耗時 N 秒」只算翻譯，但結果要等翻譯範例也產生完（最多再 6 次請求）才出現，使用者等的時間比數字長得多。本地模型第一次測試的秒數還混了載入模型的時間，拿來比較模型速度會失準。
- 測試時載入的本地模型，要等設定**儲存**時 `apply_config` 才會收掉。測完 A 再測 B，A 仍佔著 VRAM，`--fit` 會把 B 的部分層放到 RAM，B 也跑得很慢 —— 不論有沒有停止鈕，現在就會發生。

## 目標

- 測試中按鈕改成〔停止測試〕，按下就中斷，回到還沒測試的狀態（不顯示錯誤）。
- 測試中改了連線欄位、或表單關掉（服務對話框關閉、精靈換掉表單、設定視窗關閉），測試一併中斷，不再讓請求在背景跑完（本地模型的載入不中斷，見下）。
- 翻譯一回來就顯示結果；翻譯範例改在背景產生，測試後儲存仍能直接用快取。
- 本地模型把載入與翻譯分開計時：這次有載入時顯示「連線成功（耗時 2.1 秒，載入模型另花 35.0 秒）」，已載入時照舊只顯示翻譯耗時。
- 只為測試而載入的本地模型（不在已套用設定裡的）不留著佔記憶體：開始新的測試、按停止測試、設定視窗關閉時收掉。

## 非目標

- 用 B 取代設定中正在用的 A 時，A 仍佔著記憶體、B 的測試偏慢：A 正在負責實際翻譯，測試時不停它。
- 測試以外的翻譯請求加停止功能。

## 設計

### 中斷：表單持有測試的 drop guard

- `SettingsEnv::test_connection` 回傳一個 `TestHandle`（包 `tokio_util` 的 `CancellationToken` 的 drop guard）。表單把它存在 `ServiceForm` 裡；丟掉 handle 就中斷。
- 這樣表單在哪裡被丟掉（服務對話框關閉、精靈換掉表單、設定視窗關閉）都會中斷，不必一一找關閉點。
- 〔停止測試〕與測試中改了連線欄位：表單丟掉 handle、`test_round.cancel()`（立刻解除忙碌、之後回來的結果丟掉）、清掉結果，記 log。
- 背景工作被中斷時不投遞 `TestDone`（表單已不在等它）。

### 結果先顯示、範例在背景

- `RealEnv` 的測試工作：翻譯成功就投遞 `TestDone`，接著在同一個工作裡產生範例。
- 範例階段不受表單的 handle 控制（關掉表單後儲存，要能命中快取），改由 `RealEnv` 記住「上一次測試的範例工作」：開始新的測試時取消它，讓上一次測試的模型不在背景搶 GPU。
- `test_translate` 只翻那一句；範例改由 `examples_after_test` 產生（可取消，失敗與取消都只記 log）。

### 本地模型：先載入再計時翻譯

- 本地服務的測試先記下模型是否已在跑，再呼叫 `Local::ensure` 並計時；原本沒在跑才把這段當「載入耗時」。
- 已在跑但閒置睡著（`--sleep-idle-seconds` 卸載了模型、程序還在）：以 `/props` 的 `is_sleeping` 判斷（沿用 `LocalClient` 的查法），睡著就先送一個只生成 1 個 token 的請求叫醒它，這段也算「載入耗時」。開了閒置卸載的使用者玩完再開設定測試目前的模型，幾乎一定是睡著的。
- 之後的翻譯照舊走 `LocalClient`（此時 ensure 立即返回、模型醒著），只計這段為翻譯耗時。
- `TestOutcome` 多一個 `load: Option<Duration>`；有值時顯示新字串 `test.connected_loaded`（三個語系都補）。

### 收掉只為測試載入的模型

- `Local` 在 `apply_config` 記下已套用設定引用的模型（現在算完就丟），新增 `release_unused(keep: Option<&str>)`：停掉不在其中、也不是 `keep` 的 llama-server（含載入中的）。
- 呼叫時機：
  - 本地服務開始測試前：`release_unused(Some(要測的模型))`。
  - 使用者按〔停止測試〕時：表單送 `Command::ReleaseUnused`（`release_unused(None)`）。正在用的模型不受影響。
  - 只是改了欄位或表單關閉：只中斷翻譯請求，模型照樣載完。例如測試中切了思考開關，模型沒換，不該把載入進度丟掉；換了模型的話，下一次測試開始或設定視窗關閉時自然會收掉（使用者同意的修正）。
  - 設定視窗取消、儲存：本來就會重新 `apply_config`，照已套用的設定收掉。精靈取消會結束程式，不必另外處理。

## 測試

- 表單：測試中按鈕是〔停止測試〕、可按；按下後回到未測試、不顯示錯誤，之後回來的 `TestDone` 丟掉；測試中改欄位與丟掉表單都會中斷（假 env 記錄 handle 被丟掉）；本地測試只有按停止才送 `ReleaseUnused`。
- 結果顯示：`load` 有值時用含載入時間的字串。
- 本地 runtime：`release_unused` 只停不在設定裡、也不是 `keep` 的模型（用既有的假 launcher）。
- 實機：本地大模型測試中按停止、換另一個模型測試，`app.log` 看得到前一個 llama-server 被停掉；雲端服務測試後立刻儲存，範例快取命中。
