# 多帳號一鍵登入（略過官方啟動器）

## 目的

使用者想一鍵開好自己的多個帳號並直接登入，不用每次開官方啟動器、輸入帳密、按 Play。

本專案是開源專案，要照顧所有使用者：

- 帳號類型：官網註冊的帳號、透過 Steam 建立或綁定的帳號都要支援。
- 安裝來源：從官網安裝、從 Steam 安裝的遊戲都要支援。

遊戲用戶端內建的登入框早已停用，所以本工具自己向登入伺服器取得登入憑證（UserID 與 ck2），再用與官方啟動器相同的命令列參數直接啟動 `WizardGraphicalClient.exe`。

## 目標／非目標／反目標

- **目標**
  - 管理帳號：設定裡新增「遊戲帳號」頁，可新增、編輯、刪除帳號；密碼加密存放。
  - 一鍵開啟：選好的帳號一次全部登入並開進遊戲（官網帳號並行、Steam 帳號逐一）。
  - 防重複開啟：已在執行的帳號（不論是誰開的）不能再開一次。
  - 自動找出遊戲位置：同時找 Steam 收藏庫與官網版安裝位置。
- **非目標**
  - 遊戲更新。遊戲改版後，使用者先用官方啟動器或 Steam 更新一次；之後另開項目處理（見「之後的項目」）。
  - 網頁登入備援（開官網登入頁走另一條認證訊息）。等帳密登入被擋掉時再考慮。
  - Pirate101。
  - 同時開啟綁在**不同** Steam 帳號上的遊戲帳號——Steam 用戶端一次只能登入一個 Steam 帳號，做不到，只能照實告知。
- **反目標**
  - 密碼、ck2、Steam 票據出現在 log、錯誤訊息或任何明文檔案裡。
  - 登入失敗時自行推測原因（例如「可能是遊戲沒更新」）。錯誤只顯示伺服器回傳的原文；可預知的限制寫在頁面固定提示裡。
  - 為了開帳號而干擾已在執行的遊戲。

## 限制

- **服務條款風險**：這是自行實作官方登入協定，違反服務條款的程度比讀記憶體更直接。README 要照實寫明風險，由使用者自行決定是否使用。
- **Steam 帳號的前提**：Steam 用戶端要開著，且登入的是該遊戲帳號綁定的 Steam 帳號。票據靠遊戲目錄 `Bin\steam_api64.dll` 取得（本專案不散佈 Steam SDK 檔案）。官網版的 `Bin` 也附同一個 dll（用戶端主程式也相同），所以 Steam 帳號在兩種安裝上都能開。安裝來源依位置判斷（Steam 版在收藏庫的 `steamapps\common` 底下），不能看 dll。
- **協定可能變動**：登入協定是私有協定，官方修改時本功能會失效、要重新分析。目前觀察到的版本相關欄位全為空，所以單純的遊戲改版應該不受影響。
- **只支援 Windows、64 位元用戶端**（與本專案一致）。

## 方案

| 候選 | 怎麼做 | 不開官方啟動器 | Steam 帳號 | 並行多開 | 維護風險 | 結論 |
|---|---|---|---|---|---|---|
| 1. 自行實作登入協定 | 連登入伺服器取得 UserID 與 ck2，再用 `-U` 直接開用戶端 | 是 | 可（另取 Steam 票據） | 可 | 協定變動要重新分析 | **採用** |
| 2. 用戶端內建登入框 | 只帶 `-L` 開用戶端，再自動填帳密 | 是 | 否 | 可 | 低 | 不可行：登入框已停用（使用者確認） |
| 3. 自動操作官方啟動器 | 開啟動器、自動填表、按 Play | 否 | 要另走 Steam 路徑 | 否 | 介面一改就壞 | 不採用 |
| 4. 修改官方啟動器 | 注入或改寫啟動器批次開啟 | 否 | 不確定 | 不確定 | 高、侵入性強 | 不採用 |

選方案 1 的理由：只有它同時滿足「不開啟動器」、「Steam 帳號」、「一鍵並行」。協定只在登入當下使用一次，開進遊戲後跟官方開出的用戶端完全相同（參數已實測一致，見下節）。

## 已查證的事實

### 官方啟動器傳給用戶端的參數（實測）

| | Steam 安裝 | 官網安裝 |
|---|---|---|
| 參數 | `-L login.us.wizard101.com 12000 -A en-US -ST -P 0 -PT 0 -U ..{UserID} {ck2} {帳號}` | `-L login.us.wizard101.com 12000 @LOCALE_PARAMETERS -A en-US -PT {秒} -U ..{UserID} {ck2} {帳號}` |
| 安裝位置範例 | `<Steam 收藏庫>\steamapps\common\Wizard101` | `D:\ProgramData\KingsIsle Entertainment\Wizard101`（磁碟機不固定） |
| 啟動器 | 開完遊戲就結束 | `WizardLauncher.exe` 一直開著 |

- UserID 為 13 位數字、ck2 為 88 字元，`-U` 格式兩版相同。
- 用戶端工作目錄是 `Bin\`。
- 用戶端 usage 字串：`-P <0|1>` 遊戲內更新（官網版邊玩邊下載、必開；Steam 版由 Steam 下載完整檔、關閉）、`-PT` 啟動器本次更新秒數、`-ST` Steam Required、`-A` 語系。`@LOCALE_PARAMETERS` 是官方沒替換掉的佔位字，不必照抄。

### 本工具採用的啟動參數規則

- **Steam 安裝**：`-L login.us.wizard101.com 12000 -A en-US -ST -P 0 -PT 0 -U ..{UserID} {ck2} {帳號}`。Steam 沒開時拿掉 `-ST`，遊戲照常進得去，只是不記遊玩時數。
- **官網安裝**：`-L login.us.wizard101.com 12000 -A en-US -PT 0 -U ..{UserID} {ck2} {帳號}`，不寫 `-P`（遊戲內更新維持預設開啟）。我們未執行更新，`-PT` 照實填 `0`。

### 登入協定

連線、握手、認證、回應的實際封包格式**不寫進本文件**，由實作時參照既有分析產物與 Subata（Lite 2.4.7）反編譯結果完成，並寫進 `src/game/login/` 的模組與行內註解。要點：

- 以 TCP 連 `login.us.wizard101.com:12000`，完成握手後送出認證訊息，伺服器回覆帶 UserID 與 ck2；取到後即以上節參數啟動用戶端。
- 官網帳號走帳密認證；Steam 帳號在認證訊息中附上 `steam_api64.dll` 取得的票據。
- 來源分析產物：IL 反組譯 `il_all.txt`、認證訊息欄位定義（遊戲 `Root.wad` 內 `LoginMessages.xml` 的 `MSG_USER_AUTHEN_V3`／`MSG_USER_AUTHEN_RSP`）。

## 設計

### 模組切分（reader／composer／translator 各司其職的既有風格）

新增 `src/game/login/`（或 `src/launcher/`，實作者定），內含互相獨立、可單獨測試的部分：

1. **帳號儲存**（`accounts`）
   - 每筆帳號：穩定 `id`（沿用 service 既有「`id` ＋可編輯 `name`」慣例，含空白／重複處理）、`name`、類型（官網／Steam）、加密後的密碼。
   - **`name` 就是登入帳號名**（官網與 Steam 帳號都要帳密），不另設顯示標籤——使用者輸入的名稱同時是登入用帳號名，也是啟動參數 `-U` 末段的 `{帳號}`，執行中偵測就靠它比對。Steam 帳號除帳密外，登入時再臨場取票據，不需預存額外欄位。
   - 密碼用 Windows DPAPI 加密（`CryptProtectData`／`CryptUnprotectData`，`CRYPTPROTECT_UI_FORBIDDEN`），只有同一 Windows 使用者解得開。沿用 config 既有的讀寫與驗證路徑。
   - 「上次勾選」的帳號集合也存這裡。
2. **遊戲位置偵測**（`install`）
   - 先讀 Steam：`HKCU\Software\Valve\Steam` 的 `SteamPath` → `steamapps\libraryfolders.vdf` 逐一收藏庫找 `steamapps\common\Wizard101`。
   - 再找官網版：`ProgramData\KingsIsle Entertainment\Wizard101`（列舉各磁碟機，不只 C）。
   - 都找不到才讓使用者手動選。沿用既有的 `src/game/process.rs::install_root` 風格判斷目錄有效性（含 `Bin\WizardGraphicalClient.exe`、`Data\GameData`）。
   - **可能同時偵測到 Steam 版與官網版**，兩者安裝路徑都記下來（不是單一來源）。launch 時依帳號類型選目錄與參數：Steam 帳號優先用 Steam 版目錄，沒有時用官網版目錄（加 `-ST`、不加 `-P 0`，遊戲內更新照常）；官網帳號優先用官網版目錄（參數與官方一致、遊戲內更新照常），沒有官網版時用 Steam 版目錄配官網參數（Steam 版檔案已完整，不加 `-ST`、不加 `-P 0`）。
3. **登入連線**（`login`）
   - 純協定：輸入帳號憑證與（Steam 帳號的）票據，輸出 UserID 與 ck2 或錯誤。TCP、握手、認證訊息組法都在這裡；不碰 UI、不碰程序啟動。可用假 stream 做純解析測試。
4. **Steam 票據**（`steam`）
   - 在本程序內 `LoadLibrary` 遊戲 `Bin\steam_api64.dll`，設環境變數 `SteamAppId`／`SteamGameId` 為 `799960` 後 `SteamAPI_InitFlat`，再取 Web API 票據與 SteamID。這是 Subata Lite 在非 Steam 啟動的獨立程序裡實測可行的做法（靠 `SteamAppId` 環境變數、不需 `steam_appid.txt`），不必另丟 helper exe。
   - 前提不符（Steam 沒開、未登入）時回明確錯誤。
   - **票據永遠來自「目前登入 Steam 的使用者」**：一鍵勾了多個分屬不同 Steam 使用者的 Steam 帳號時，只有對應當前 Steam 登入者的那個會成功，其餘由伺服器以原文回拒（本次不預先比對 SteamID 擋下，保持簡單；日後要更友善可預存各帳號 SteamID 先行比對）。多數人只有一個 Steam 帳號，不受影響。
5. **用戶端啟動**（`launch`）
   - 依安裝來源組參數、設工作目錄為 `Bin\`、啟動 `WizardGraphicalClient.exe`。
6. **執行中帳號偵測**（`running`）
   - 列舉 `WizardGraphicalClient.exe`，讀各程序命令列、解析出 `-U` 末段的帳號名稱，比對已存帳號的 `name`，判斷哪些正在執行。
   - 讀命令列是新增能力：`process.rs` 目前只用視窗類別／模組路徑辨識，沒有讀命令列。實作走 PEB ＋ `ReadProcessMemory`（`mem_reader` 已是此路數）或 WMI，實作者定。
   - **命令列含 ck2，讀取時整段會進本程序記憶體；解析出帳號名後即丟棄，ck2 絕不落地、絕不寫 log。**
   - 開啟遊戲帳號視窗開著時定時掃描、按開啟前再掃一次。遊戲關掉後程序消失，狀態自動恢復，不另存狀態。

### 一鍵開啟的流程

- 官網帳號並行登入；Steam 帳號逐一（Steam 一次一票據）。
- 逐帳號顯示結果：成功「已開啟」、進行中「登入中」、失敗顯示伺服器原文。單一帳號失敗不影響其他帳號。
- 已在執行的帳號跳過並停用勾選，不計入「開啟 N 個帳號」。
- 遊戲視窗出現後，既有的 reader supervisor 本來就每個視窗各開一條執行緒，多開後每個視窗都翻得到，不改。

### UI（沿用 egui 設定視窗與 overlay 既有元件與配色）

介面定稿見本次對話的設計稿。摘要：

- **設定 → 遊戲帳號頁**：遊戲位置卡（顯示偵測結果、可變更）＋帳號清單（每列：名稱、類型徽章、單獨「開啟」、「編輯」、「刪除」）＋「新增帳號」＋「開啟後自動關閉帳號視窗」開關。執行中的帳號標「執行中」、單獨開啟停用。底部固定 Steam 限制說明（全形標點）。名稱清空要擋存檔（沿用既有命名欄位的紅字擋存規則）。
- **新增／編輯對話框**：帳號類型（官網／Steam 分段切換）、名稱、密碼（可顯示）。依類型顯示對應說明。
- **overlay 開啟入口**：標題列常駐 ▶，並在「等待遊戲中」時於內容區中央放大按鈕「▶ 開啟遊戲」。兩個入口都打開**同一個獨立視窗**「開啟遊戲帳號」（與設定視窗同樣式、開在螢幕中央；已開著就叫到前景），不在 overlay 裡畫彈出選單，overlay 縮成泡泡時視窗照常開著。
  - 頂端「全選」、底部「開啟後自動關閉此視窗」與「開啟 N 個帳號」固定，中間帳號清單捲動；名稱過長以「…」截斷。視窗最小尺寸至少看得到兩列帳號。
  - 每列：勾選框、名稱、類型徽章、執行中徽章與單獨〔開啟〕；執行中或登入中的帳號停用勾選與〔開啟〕。進度與錯誤顯示在該列下方，失敗只顯示伺服器原文。
  - 「全選」只勾未執行的帳號，部分勾選顯示「−」。按鈕數字＝實際會開的數量（排除執行中），0 時停用。勾選記住上次選擇。
  - 沒有帳號時顯示〔前往新增帳號〕，直接開設定視窗的遊戲帳號頁（設定視窗已開著就切頁並叫到前景）。
- **自動關窗**（設定鍵 `launch_auto_close`，沒設定過視為開）：從這個視窗開的帳號（批次或單獨，開啟中再開的併入同一批）全部有了結果、且沒有失敗（已開啟、已在執行都算成功）就關窗；有失敗則留著讓錯誤看得到。手動關窗就不再等這一批。開關在視窗底部（改了立即存檔）與設定的遊戲帳號頁（隨設定視窗一起儲存）各有一個，兩邊同步：視窗改了會同步到開著的設定頁且不算未存的變更，設定儲存後視窗讀共用設定。這個鍵與 `accounts`／`launch_selection` 一樣不進預設設定，讀取時給預設值。

### 錯誤與 log

- 在關鍵節點埋英文 log（沿用既有前綴，如 `[launch]`／`[login]`）：偵測到的安裝位置與來源、登入連線的 provider 與伺服器回應碼／錯誤分支、Steam 票據取得失敗、啟動程序 PID、重複開啟的攔截判定。
- **log 與錯誤訊息一律不含密碼、ck2、Steam 票據。** 讀命令列時只擷取帳號名稱。
- 使用者看得到的錯誤字維持繁體中文全形；登入失敗只顯示伺服器原文，不加推測。

## 之後的項目（本次不做）

- **遊戲自動更新**：官方做法是取檔案清單、逐檔比對 CRC、下載有變動的檔案（安裝目錄 `PatchInfo\` 存各 wad 的 CRC）。做這項時，`-PT` 要改成「本次更新實際花的秒數」，與官方啟動器一致。本次先在登入失敗時提示使用者用官方啟動器或 Steam 更新一次。
- **網頁登入備援**：帳密登入被擋時，開官網登入頁走另一條認證訊息。

## 留給實作者的決定

- 新模組的確切路徑與命名（`src/game/login/` 或 `src/launcher/`）。
- 握手 sid 欄位的實際寬度，以實測封包確認後定案。
- DPAPI 封裝的細節沿用 config 既有加密（若已有）或新加，由實作者視現況定。
