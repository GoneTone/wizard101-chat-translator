# 簡體中文術語表的繁體配對

## 動機

目前沒有繁體中文漢化包，台灣玩家多半也套 Subata 的簡體漢化包，但打字用繁體。術語表比對是逐字的，繁體的「克洛克托比亞」對不上內建表的「克洛克托比亚」：收訊（英翻中）不受影響，發話（中翻英）會漏掉術語。加一個開關，一方面讓使用者知道繁體也配得上，一方面讓使用者自己決定要不要開。

## 目標

- 術語表引入簡體中文內建表（`zh-CN`）時，設定畫面多一個「繁體也能配對」的開關，預設打開。
- 開關打開時，這份術語表所有用到正規化比對的地方一律先把繁體字轉成簡體字：翻譯時的比對、自訂蓋過內建的判定、條目重複檢查、匯入合併的比對。

## 非目標

- 不轉換送給 AI 的原文或術語，轉換只用於比對。
- 不做簡轉繁、不做其他語言的字形配對。
- 編輯畫面的搜尋框不受開關影響。

## 反目標

- 開關打開後，同一個詞的繁、簡兩條同時送進提示詞，或畫面上看不出自訂已蓋過內建。
- 簡體、英文、日文等原本配得上的輸入，打開開關後反而配不上。

## 做法比較

- **開關出現的時機**：
  - **B. 程式直接判斷引入的內建表是不是 `zh-CN`（採用）**：只有簡體中文術語表會用到，屬於例外，程式碼裡註明原因。
  - A. 內建表檔案自己宣告支援繁簡配對：不寫死語系，但要讓檔案格式多認一個鍵，目前沒有第二份需要的表。
  - C. 每份術語表都顯示：只用英文或日文的人也會看到無關的選項。
- **開關的影響範圍**：
  - **1. 跟著整份術語表走（採用）**：比對、覆蓋判定、重複檢查、匯入合併一致套用，前後不會矛盾。
  - 2. 只有比對看開關：改動最少，但打繁體時自訂與內建兩條會同時命中、畫面也看不出是同一個詞。

## 設計

- **轉換**：用 `hanconv`（MIT、無相依、OpenCC 字表與詞表），先 `s2tw` 再 `tw2s`。只做 `tw2s` 不會收斂：簡體「颚」維持不變，繁體「顎」卻轉成「腭」，兩邊對不上。非標準的異體寫法（例如「馬夫」對標準的「馬伕」）不在處理範圍內。
- **正規化**：`fold` 之外多一個帶開關的正規化函式；開關打開時先做 `tw2s` 再去空白、casefold。`Glossary::new`、`review`、`overridden` 與匯入合併的比對都多帶這個開關。
- **例外：「與內建相同、存檔自動移除」不套用轉換**：只有字完全相同才算。否則開關打開時，使用者特地補的繁體條目（例如自訂 `Dragonspyre → 龍之谷`、內建 `Dragonspyre → 龙之谷`）會在存檔時被刪掉。這種條目照一般規則處理：英文相同，所以自訂蓋過內建；編輯畫面顯示黃色的內建譯名提示。
- **只差繁簡的同一條整條讓給自訂**：自訂與內建 fold 後兩側相同（例如自訂 `Dragonspyre → 龍之谷`、內建 `Dragonspyre → 龙之谷`），比對器直接略過那條內建，不會兩條一起送。
- **同義詞規則不變**：英文不同、中文轉換後相同（例如自訂 `Dspyre → 龍之谷`、內建 `Dragonspyre → 龙之谷`）照原術語表設計當同義詞，命中中文時兩條都送。
- **設定**：存在每份術語表裡，跟引用的內建表代碼放在一起；沒有這個欄位時當作打開。引入的內建表從 `zh-CN` 換成別的或不引入時，開關隱藏、不做轉換，但存著的選擇保留；換回 `zh-CN` 時沿用原本的設定。匯出的檔案不帶這個開關（匯出格式就是內建表格式）；複製術語表時一起複製。
- **介面**：放在「引入內建術語表」那一列正下方，只有引入 `zh-CN` 時才出現，附一行說明。新字串要補到每個有翻譯術語表區塊的語系檔。
- **啟用流程**：`config::glossaries::active` 在引入 `zh-CN` 且開關打開時，建構時帶入開關，並記 log。

## 測試

- 用 `zh-CN` 內建表的實際條目驗證：繁體寫法不論單獨出現、還是夾在句子裡，都要配得上。這是為了確認 `tw2s` 的詞組轉換不會讓單獨轉與在句中轉的結果不同。
- 簡體、英文、日文輸入在開關打開後照常配對。
- 開關打開時，自訂的繁體條目蓋過內建的簡體條目，只送出自訂那一條；開關關閉時維持現有行為。
- 開關打開時，自訂的繁體條目與內建的簡體條目只差在繁簡，不會被判成「與內建相同」，存檔後仍保留。
- 沒有開關欄位的舊設定讀出來是打開；複製術語表時保留開關。
- 量打包後 exe 增加的大小，寫進 PR 描述。
