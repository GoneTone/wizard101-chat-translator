# 多張顯示卡的 VRAM 估算

## 目的

llama-server 沒指定 `--device`／`--split-mode`，llama.cpp 預設就會把模型按層分到所有看得到的 GPU，`--fit` 也依各卡可用量分配。但本程式估算 VRAM 時只看一張卡（`detect_gpu` 取第一張獨顯、`pick_device` 只挑一個裝置），多卡使用者的相容等級與自動選量化因此偏保守。另外本程式自己的佔用（`own.vram`）是所有卡合計，卻加回單張卡的可用量，兩邊對不上。

目標是讓估算與引擎實際行為一致：引擎會用到幾張卡，就把那幾張的 VRAM 加總。

## 目標與非目標

- 目標：多張獨顯時，總量、可用量、`--fit` 預留量都按引擎會用的卡加總；設定頁列出所有用到的卡。
- 目標：單卡行為與數字完全不變。
- 非目標：逐卡模擬分層（每卡各自的運算暫存區、層不可切半）—— 模型載入一次後等級改用實測，誤差只影響下載前的推薦。
- 非目標：讓使用者選卡、避開遊戲所在的卡、改 `--split-mode`。沒有需求，等回報再做。

## 做法比較

- **A. 加總引擎會用到的卡（採用）**：改動集中在 `src/local/hardware.rs` 與 `hub.rs`，單元測試用假裝置清單即可驗證。代價是略樂觀，靠載入後的實測修正。
- B. 逐卡模擬 llama.cpp 分層：較準，但需每層大小等資料、程式碼多很多，且維護者沒有多卡機器可驗證。
- C. 強制單卡（`-sm none`）：估算與行為一致、改最少，但拿走多卡使用者現在已經享有的第二張卡。

## 設計

- **偵測**：`detect_gpu` 改成回傳所有獨顯（沒有獨顯才回內顯那一張）。`Hardware.gpu` 保留為第一張，需要單一張卡的地方（`auto_variant` 選 CUDA／Vulkan、是否為內顯）照用，行為同現在；另加 `vram_cards: Vec<String>` 記下算數的卡名（長度即卡數）。
- **哪些卡算數**：
  - 沒裝引擎：所有偵測到的獨顯。
  - 裝了引擎：`--list-devices` 列出、且名稱對得上偵測到的獨顯的那些（同名多張逐一配對）。CUDA 版只列 NVIDIA，混搭 AMD 時自然只算 NVIDIA；Vulkan 版列出的內顯對不上獨顯，不算。
  - 一張都對不上：退回現在的行為（取記憶體最大的單一裝置）。
- **數字來源**：同現在，系統計數器優先、讀不到才用引擎回報。逐張讀 DXGI 計數器後加總；任一張讀不到就整組改用引擎數字，不混用。相同型號的兩張卡要各自對到不同的 DXGI adapter（LUID），不能重複讀同一張。
- **`--fit` 預留**：`usable` 扣的 `FIT_TARGET` 乘上算數的卡數；`Hardware` 記下卡數。
- **設定頁**：「顯示卡」那行列出算數的卡；同型號寫成「名稱 ×2」，不同型號用「 + 」連接（不必為各語系準備分隔字）。
- **log**：`[local] hardware:` 那行改記所有卡名與算數的卡數；`VRAM sources:` 那行照記逐卡的計數器與引擎裝置。

## 測試

單元測試（不需多卡硬體）：

- 兩張同型號獨顯：總量、可用量加總，卡數 2。
- 獨顯加內顯（Vulkan 都列出）：只算獨顯。
- NVIDIA 加 AMD、引擎只列 NVIDIA（CUDA 版）：只算 NVIDIA。
- 名稱全對不上：退回取最大的單一裝置。
- 任一張計數器讀不到：改用引擎數字。
- `usable` 依卡數扣預留。
- 單卡的既有測試數字不變。

## 留給實作者

- `Hardware` 裡卡數的欄位名稱與型別。
- DXGI adapter 與偵測結果的配對細節（目前以 vendor／device ID 比對，同型號多張時要逐一消耗）。
