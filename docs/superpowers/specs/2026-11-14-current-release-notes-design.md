# 關於頁查看本版更新內容

## 目的

使用者想回頭看「目前用的這一版改了什麼」時，不必自己去 GitHub 找。在設定視窗的關於頁加一個入口，點下去開一個視窗，只顯示目前執行版本的版本說明。外觀沿用更新視窗。

## 範圍

- **入口**：關於頁頭卡的版本號後面接一個連結，變成「版本 v1.3.1 · 本版更新內容」。頭卡版面與〔檢查更新〕按鈕維持不變。
- **視窗**：獨立視窗，外框沿用更新視窗：
  - 視窗標題「{app} — 本版更新內容」。
  - 標題區：大字「v{version} 更新內容」，副標「目前使用的版本」。
  - 內容只有一張 release 卡片，與更新視窗的卡片相同：版本號、發布日期、Markdown 內文，不加「最新」標籤。
  - 底部列只放〔在 GitHub 上查看〕與〔關閉〕（主按鈕），沒有下載相關按鈕。
- **內文**：開視窗時才向 GitHub 取目前版本的 release。整份顯示，與更新視窗相同（包含 What's Changed、回報問題、貢獻翻譯）。
- **卡片位置的狀態**：
  - **載入中**：標題區與卡片上的版本號照常顯示（本機已知）。發布日期與內文改用佔位色塊（`widgets::skeleton`），不顯示「正在載入…」文字。內文的色塊排成兩段，每段一條標題列加幾條長短不一的內文列，像草圖那樣。
  - **載入失敗**（連線錯誤、HTTP 非 200／404、回應無法解析）：卡片裡顯示伺服器原文，附〔重試〕，沿用 `widgets::error_with_retry`。錯誤訊息不加推測的原因。
  - **找不到**（HTTP 404：原始碼執行時版本號還沒打 tag、release 被刪、草稿）：卡片裡顯示灰字「GitHub 上找不到 v{version} 的版本說明」，不放〔重試〕。
- **〔在 GitHub 上查看〕**：開這一版的 release 網頁（API 回傳的 `html_url`）。還沒取到內文或找不到時，開 releases 列表頁。
- **記住內容**：這次執行期間載入成功一次後，之後關掉再開都直接顯示，不重新請求。失敗或找不到的結果不記住，下次開視窗會重新取。
- **重複開啟**：視窗已經開著時再點連結，把它叫到前景，不重設狀態、不重新請求。
- 尺寸與最小尺寸沿用更新視窗（620×600，最小 480×360）。
- **與設定視窗各自獨立**（我的判斷）：關掉設定視窗不會連帶關掉這個視窗，跟更新視窗目前的行為一致。
- **失敗文字的格式**（我的判斷）：跟檢查更新共用同一套錯誤字串。非 200 一樣只顯示 `HTTP {code}`，不另外解析 GitHub 回應裡的 `message`。兩邊要改就一起改。

## 不做

- 更新後重新啟動時主動跳出本版說明。使用者明確表示只要關於頁上的一個按鈕。
- 依介面語言只顯示 release 內文中的某一種語言。內文照原樣整份顯示。
- 瀏覽其他舊版本的說明。

## 做法

使用者在草圖上比較過入口與顯示方式：

- 入口：A 頭卡加第二顆按鈕（會壓窄名稱欄）、**B 版本號後接連結**、C 連結卡片新增一列（離版本號遠、撐高卡片）。
- 顯示：**X 獨立視窗**、Y 在關於頁內展開（版本說明很長，會把下面的設定列推得很遠）。

使用者選了 **B＋X**，載入中改用佔位動畫。

## 實作要點（交給實作者，下列是我的判斷）

- **取資料**：在 `runtime/updater.rs` 加一個查單一 release 的函式，打 `{RELEASES_API}/tags/v{CARGO_PKG_VERSION}`。HTTP 200 → `Release`、404 → 找不到、其他 → `UpdateCheckError`。請求標頭與 client 沿用 `check_for_update` 與 `update_client`。從 `parse_releases` 抽出單筆 JSON 轉 `Release` 的部分共用，不要另寫一份欄位解析。單筆查詢不套用 `is_newer` 與 pre-release 過濾：tag 端點不回草稿，而目前執行的版本就算是 pre-release 也該顯示。
- **視窗托管**：新增一個 host（例如 `src/ui/release_notes_host.rs`），用 `HostedWindow` 與一個新的 `Spec`，模式參照 `UpdateHost`，但不碰 `UpdateJob`。它自己持有 tokio `Handle` 與 `UiPoster`，在背景取資料，結果以新的 `UiEvent` 投遞回 UI 執行緒。要用輪次（或等效機制）丟掉過期的結果，例如關窗後才回來的那一次。
- **跟更新視窗脫鉤**：`main.rs` 在除錯建置或找不到自己的 exe 時不會掛上 `UpdateHost`。本版說明的 host 不能依賴這個條件，`cargo run` 時也要能開，這樣才看得到「找不到」的畫面。
- **App 串接**：關於頁送出新的 `SettingsAction`（例如 `OpenReleaseNotes`），App 呼叫 host 的 `open`，並每幀呼叫它的 `show`。overlay 置頂層級的判斷（`app.rs` 裡「設定或更新視窗開著就降為一般層級」那段）、`viewport_hwnds` 都要把新視窗算進去。
- **共用卡片**：把 `UpdateView::release_card` 與它用到的 `flatten_headings`、`local_date`、Markdown 樣式設定抽成兩個視窗共用的函式。用參數決定要不要畫「最新」標籤。載入中的佔位版本可以是同一個函式的另一個分支，或另一個小函式，由實作者決定。標題區與底部列的外框（內距、底色、`scroll_page`）也盡量共用常數，不要複製數值。
- **關於頁連結**：`hero_text` 的版本號那一行改成「版本 v{version} · 」接一個 `Link`。連結文字大小與版本號相同，用 `theme::LINK`。點下去記一筆 log。
- **介面文字**：新增的字串（連結文字、視窗標題、標題區、副標、找不到的提示）要補到所有已經翻譯關於頁、更新視窗字串的語系檔，不只繁中與英文。載入失敗的文字可沿用既有句型或新增 key，由實作者判斷，但要跨語系一致。
- **log**（英文、`[update]` 前綴）：開窗／叫到前景、開始請求（帶版本）、成功（帶發布日期）、404、失敗（帶錯誤原文）、使用快取、開 GitHub 網址、關窗。
- **測試**：
  - 單筆 release 解析：200／404／非 200／壞 JSON。可用既有測試對 `check_for_update` 的方式。
  - kittest：點關於頁連結會開視窗。載入中有佔位、無「正在載入」文字；成功顯示內文；404 顯示找不到、沒有〔重試〕；失敗有〔重試〕且按下會重新請求；再開時用快取不再請求。
  - 新的整合測試放 `tests/it/`。

## 驗收

- 關於頁版本號後出現連結。點下去開視窗，載入中顯示佔位色塊，之後顯示這一版完整的版本說明，外觀與更新視窗的卡片一致。
- 離線時顯示錯誤原文與〔重試〕。原始碼執行（版本未打 tag）時顯示找不到的提示。
- 除錯建置也能開這個視窗。
- `cargo fmt --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test` 全過。
